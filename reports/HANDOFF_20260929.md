## 目标和当前结论

最终目标是让 6+5 IMU 智能服经人体参考、Sonic policy 和 X2 底层控制实现全身遥操。
目前衣服到 Sonic 的**无 HAL 输出 dry-run**已跑通；旧模型的固定 StandStill 在
特定吊绳支撑下有长时记录，但**无吊绳自主承重、真机带电衣服闭环、全身动作和行走
均未验收**。控制侧目前应先复核固定支撑站立，再考虑静止穿衣者的第一段闭环。

```text
上衣/裤子 V2 BLE -> X2 SoC1 AX210 + CUDA LFP
  -> X2 3588S postprocess + Fast-SMPL + native GMR (G1 qpos36)
  -> SoC1 timestamp HMCP -> G1-to-X2 按名字的增量映射 (pose-scale=0.7)
  -> raw ZMQ :5555 -> safety proxy <-> x2_debug :5557
  -> guarded ZMQ :5556 -> Sonic 50 Hz -> 唯一 HAL writer 250 Hz -> X2
```

Mac/5060 不在目标实时控制链。3588S 只生成参考；机器人反馈、policy 和 HAL writer
仍在 SoC1/SoC0 的既有控制路径内。

## 两代 Sonic 不可混用

- 现有 X2 部署历史基线是 `p3_8900 frozen-G1core + LoRA`，模型
  `x2_sonic_frozen_g1core_lora_v2.onnx`，SHA-256
  `8ccc42a82ea2c446aa708aece58c7a638ea943a79ed88eeab259669e641271e9`。
  它和 `neutral_damped`、reconstructed pelvis、50/250 Hz、实际 action/PD
  配置共同构成一套身份。权重不在 Git。
- 作者后来公开的 [Sonic transfer v0.2](https://sonic-agibot-x2.github.io/sonic-transfer/)
  报告了新的 X2 真机运动结果；这属于**作者公开证据**，不是本项目复现。
  后期 `s1ft16000` 与这里的 `p3_8900` 不同。要评估新版本，先收齐匹配的
  checkpoint、SMPL tokenizer/pose actor、plant、观测与部署参数，再做离线契约测试；
  不得把单个新 ONNX 换进旧 launcher，也不能由真机行走视频推论衣服全身遥操可用。
- 用户提到另有一个在 G1 上经 Sonic 验证的 SMPL 输出模型。这是有价值的候选，
  **目前本仓库没有其可核验的文件路径、哈希或预处理/时序契约**；X2 复用尚未验证。

新模型或从头训练时优先核对：SMPL/root 坐标与四元数约定、关节顺序和默认角、
训练时实际采样的人体参考分布、future window/速度时间戳、action scale/clip、
X2 电机和踝/腰力矩约束、PD/频率/观测与部署的一致性。姿态重定向正确或 MuJoCo
`mj_forward` 画面正确，均不等于接触动力学下能平衡；真实支撑力和执行器跟踪误差
需要独立测量。不要把旧 `p3_8900` 的失败直接归咎于新版本，也不要以调大 slew
作为默认修复：历史对照中 `0.30 rad/s` 的踝跟踪误差和速度反而更大。

## 接手顺序

1. 先读根目录 [AGENTS.md](../AGENTS.md)、[报告索引](README.md)、
   [最新决策 D-017](../script/sonic_x2_transfer_v2/GR00T_audit/docs/DECISIONS.md)
   和 [操作规范](../script/sonic_x2_transfer_v2/GR00T_audit/docs/OPERATIONS.md)。
   2026-08-31 最后记录是 writer 退出后 MC publisher 消失、随后断线；更早的
   “MC 已恢复”记录不能覆盖它。接手时先获取新鲜状态，绝不能假设已有控制权。
2. 离线整理 G1 SMPL 候选和公开 v0.2 的完整工件身份，做输入/输出、关节映射、
   数值及延迟对照。新路线单独建实验记录，不覆盖旧基线或现有安全代理。
3. 旧路线的下一项受控实机问题是 D-017：**在 Policy OFF 时**定好脚底接触和
   吊绳支撑，进入 Policy 后保持物理支撑不变。固定 100 秒 wrapper 仅经过本地
   离线验证；其机器人端同步、哈希和 MC 归属必须重新核对。最终候选同一二进制
   300 秒验收及 approved manifest 尚未完成。
4. 只有父版本验收和批准 manifest 均成立，才可考虑受支撑、穿衣者静止的
   10 秒 blend；通过后再单独做小幅动作。第一次上电实验不能跳过 proxy，
   也不能把 dry-run 的 35 Hz 当作带电闭环证据。

实机任何时候只能有一个 HAL writer；电池更换/重启会使旧 session、ready sentinel
和 arm 状态失效。实机动作必须按操作规范重新取得现场确认。本交接文档不提供
启动命令，也不批准任何接管。
