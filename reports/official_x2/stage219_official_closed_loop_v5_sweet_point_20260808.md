# Stage219 官方 X2 MuJoCo 闭环门禁 v5

日期：2026-08-08

## 总结

在智元 AimDK v1.0 自带的 X2 MuJoCo 刚体物理环境中，最终统一矩阵完成 `9/9` 严格通过：直行、右转、左转各 3 次，每次均同时通过站立、起步、移动语义和停车门禁。

这证明当前 Stage219 后端已能在一个固定官方 nominal 域内，可复现地完成“站稳 → 起步 → 前进/转向 → 停稳”的最小闭环。它不是运动学动画，也不等价于真机、执行器随机化域或完整 SONIC reference 跟踪已经解决。

## 假设

此前左转存在欠转、过转和停车失稳分叉，不完全是 Stage219 没有运动能力；主要问题可能来自：

1. 左右结构语义没有按官方 X2 MJCF 正确对称处理；
2. gait phase 被重复平移半周期，造成 actor 与模板错相；
3. 移动 actor 切换到站立 actor 时，`previous_action` 使用了站立阶段旧值；
4. 只设转角完成率下限会把严重过转误判为成功。

## 干预

- 加入起步前 1 秒独立门禁：高度、倾角、前进量和反向窜动均需通过。
- 将移动 actor 的最后动作历史同步给站立 actor，再执行停车交权。
- 增加严格的左右镜像 contract：31DOF 状态、15 维动作、root 物理量和模板按官方 MJCF 轴约定镜像。
- 修复镜像时 gait phase 的重复半周期偏移。
- 左转复用已验证的右转能力，并单独标定为 `-0.09 rad/s`；右转为 `+0.15 rad/s`。
- 转向完成率门改为双边约束 `0.50–1.50`，防止欠转和过转都被误判。
- 将临时 `/tmp` 命令迁入项目，增加日志持久化、基础设施重试、断点续跑和 ROS Domain `0–232` 上界预检。

## 对照

- 固定差分髋偏置左转：多次出现欠转、过转或停车摔倒，v3 仅 `1/3`。
- 双向 yaw feedback：`0/3`，会跨入反向纠正或过转吸引域，淘汰。
- 单支撑相位门控：0.5 欠转、0.7 失稳，不存在已证实的稳定数值窗口，淘汰。
- 错误的镜像 phase：镜像直行倒退并倒地；去掉重复半周期偏移后镜像直行完整通过。
- v4 初始镜像左转 `-0.15 rad/s`：`2/3`，安全性已稳定但一条欠转；重新标定后再进入 v5。

## 结论

本轮的有效推进不是“把原始 reference 强行跟得更像”，而是把 Stage219 的局部运动能力整理为目标机器人专属、受限且可验证的下层技能后端。此前 reference 与平衡互相打架的问题，在最小 locomotion contract 上被绕开并形成可复现闭环；完整上肢 reference、速度连续泛化、执行器 delay/noise 和真机仍未由本结果证明。

## 下一步

1. 冻结 v5 配置作为官方 nominal 回归基线，不再在其上盲扫残差。
2. 扩展低速/中速以及上肢固定、慢摆、快摆扰动矩阵。
3. 将同一门禁移植到 nominal+delay/noise 域，区分物理模型与执行器响应退化。
4. 仅在上述扩展矩阵仍保持趋势时，解锁针对性的长训或 intent adapter 训练。
