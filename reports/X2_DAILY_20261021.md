## 二、上午：按作者方法部署策略（Stage 0 + Stage 1）

### Stage 0（08:26–08:34）：先隔离交接机制本身
双 SoC 重启获得干净系统后，双端 75s observer 先行，再以与 deploy_x2.sh 相同机制 POST stop_app（08:30:04）→ start_app（08:30:10），**全程零自定义代码**。
结果：命令静默正确；反馈在 stop 后 ~4s 崩塌且至 08:34 未自愈；IMU Publish 出现 2000.6/2016.6ms 阻塞；FastDDS SHM 端口 NOT Healthy 扩散（新 MC PID 2328→7130 被污染，六路输入收不到）。
对策：**彻底绕开 EM stop_app**，改用进程级 SIGSTOP/SIGTERM 静默（08-28 ledger 73s 连续新鲜、10-20 15:02 2.005s 有界验证过）。

### Stage 1（run1–13，全部吊起）：完整部署流程
严格走作者顺序：watchdog → kplanner → pose gate → `deploy_x2.sh --no-stop-mc` → standby 就绪 → MC 静默 → 核对命令静默+反馈新鲜 → trigger → CONTROL → Ctrl-C 软停（RAMP_OUT→HOLD_FOR_MC）→ 恢复 MC → 复核。

| run | 静默方式 | binary | CONTROL 结果 |
|---|---|---|---|
| 1–7 | SIGSTOP 调试 | 500Hz | 工具 bug/时钟 bug/归属与竞态逐项修复，未到 CONTROL |
| 8 | SIGSTOP 75s | 500Hz 原版 | 全链路走通，+1.7s stale |
| 10 | SIGSTOP 75s | 250Hz 候选 | +1.5s stale |
| 11 | SIGTERM 优雅退出 | 250Hz | ramp alpha=1.0，+3.2s stale |
| 12 | SIGTERM | 250Hz | intra-op 3，+0.7s stale |
| 13 | SIGTERM | 250Hz | 零 observer+极简 driver，+0.66s stale |

### Stage 1 结论
1. **SIGTERM 优雅交接链全部打通、多轮可复现**：standby→静默→trigger→CONTROL→软停 exit 0→start_app 恢复；EM stop_app 的传输毒化被绕开。
2. **CONTROL 期 stale 定位为 deploy 进程内部订阅饥饿**：与 writer 频率（500/250Hz）、MC 状态（冻结/退出）、intra-op（1/3）、外部监视负载均无关；同期外部订阅者全程 0.02–8ms 新鲜。
3. no-publish 计算干净 → 差异只在 writer 发令。
对策（代码级）：实施 **callback/executor 隔离**，即下午的 v02_state_executor 候选。
