Usage: x2_deploy_onnx_ref --model PATH [options]
  --model PATH               (required) fused g1+g1_dyn ONNX
  --motion PATH              X2M2 reference motion (else stand-still)
  --autostart-after SECONDS        auto-go after N seconds (else wait stdin)
  --max-duration SECONDS     auto-shutdown N seconds after entering CONTROL
                             (default: run until Ctrl-C). Useful for bounded
                             dry-run smoke tests.
  --dry-run                  publish stiffness=0/damping=0
  --tilt-cos COS             tilt watchdog threshold (default -0.3)
  --ramp-seconds SECONDS     soft-start ramp (default 2.0)
  --max-target-dev RAD       per-joint hard clamp on |target-default|,
                             in radians. Negative/omitted = disabled.
                             Use 0.05 (~3 deg) for first powered runs
                             so a divergent policy cannot drive any joint
                             more than RAD away from the standing pose.
                             Acts as the GLOBAL default for joints with no
                             per-group override below.
  --max-target-dev-leg RAD   per-group override (MJ joints 0..11 = both
                             hips, knees, ankles). >0 wins over the global
                             --max-target-dev for these joints; -1/omitted
                             = inherit. Typical pairing: leg=0.30 (~17 deg),
                             arm=1.50 (~86 deg). Legs need to stay tight
                             because their kp ~99 Nm/rad; the same
                             nominal travel produces ~7x the torque arms do.
  --max-target-dev-waist-pitch RAD per-JOINT override for waist_pitch
                              (MJ joint 13 only; wins over the waist group
                              value -- rated range 0.314 needs a tighter
                              clamp than roll/yaw can live with)
  --max-target-dev-waist RAD per-group override (MJ joints 12..14 = waist
                             yaw/pitch/roll). Same semantics as --leg.
  --max-target-dev-arm RAD   per-group override (MJ joints 15..28 = both
                             shoulders, elbows, wrists). Set this loose
                             (e.g. 1.50) for teleop where IK can drive
                             the wrist far from default.
  --max-target-dev-head RAD  per-group override (MJ joints 29..30 = head
                             yaw, pitch). Same semantics as --leg.
  --kp-scale FACTOR          multiplicative trim on the trained KP for ALL
                             joints (default 1.0). The shipped kps[] is the
                             raw IsaacLab training value; deploying it
                             unchanged loses ~1.3-1.5x of effective loop
                             gain because IsaacLab integrates PD implicitly
                             against joint inertia + armature, while real
                             X2 / MuJoCo apply explicit ctrl-driven torque.
                             See gear_sonic/scripts/eval_x2_mujoco.py:155.
                             Per-group scales below are ON TOP of this.
  --kp-scale-hip FACTOR      per-family override (joint-name contains 'hip').
  --kp-scale-knee FACTOR     per-family override (joint-name contains 'knee').
  --kp-scale-ankle FACTOR    LEGACY ankle alias. Multiplies BOTH the
                             ankle_pitch and ankle_roll subgroups (backward
                             compat with the pre-split single-knob YAMLs).
                             Prefer the split knobs below for new presets
                             because MC uses ASYMMETRIC PD across ankle
                             axes (pitch kp=40 kd=3.0, roll kp=30 kd=2.0).
  --kp-scale-ankle-pitch FACTOR  ankle_pitch_joint ONLY. Trained kp=21.38;
                             1.87 matches MC's 40 N*m/rad. The G16b-validated
                             default for sagittal-plane recovery.
  --kp-scale-ankle-roll FACTOR  ankle_roll_joint ONLY. Trained kp=21.38;
                             1.40 matches MC's 30 N*m/rad (deliberately
                             softer than pitch so frontal-plane disturbances
                             absorb without snapping the foot sideways).
  --kp-scale-waist FACTOR    LEGACY waist alias. Multiplies BOTH the waist_yaw
                             and waist_pr subgroups (backward compat with the
                             pre-split single-knob YAMLs). Prefer the split
                             knobs below for new presets -- the trained kps[]
                             differ 2.81x between waist_yaw (40 Nm/rad) and
                             waist_pitch/roll (14.25 Nm/rad), so a single
                             alias cannot match MC's uniform 40 Nm/rad
                             without over-stiffening yaw.
  --kp-scale-waist-yaw FACTOR  waist_yaw_joint ONLY. Trained kp=40.18
                             (matches MC's 40 exactly), so the typical value
                             is 1.00 -- bumping it is more likely to ring than
                             to help.
  --kp-scale-waist-pr FACTOR   LEGACY alias: applies to BOTH waist_pitch and
                             waist_roll. Trained kp=14.25, MC uses 40, so
                             2.81 matches MC exactly. Prefer the per-axis
                             knobs below for new presets -- the 2026-05-30
                             MC-vs-SONIC scan showed pitch and roll close
                             the MC gap in opposite directions (+45% on
                             pitch, -72% on roll), which the combined knob
                             cannot express.
  --kp-scale-waist-pitch FACTOR  waist_pitch_joint ONLY. Composes with the
                             legacy --kp-scale-waist and --kp-scale-waist-pr
                             multiplicatively (default 1.0 = inherit). Use
                             this to tune sagittal-lean (fwd/back) stiffness
                             independently of roll.
  --kp-scale-waist-roll FACTOR  waist_roll_joint ONLY. Composes with the
                             legacy --kp-scale-waist and --kp-scale-waist-pr
                             multiplicatively (default 1.0 = inherit). Use
                             this to tune lateral-lean (left/right)
                             stiffness; closes the -72% lateral compliance
                             gap vs MC that the combined waist_pr knob
                             can't reach without breaking pitch.
  --kp-scale-shoulder FACTOR per-family override (shoulders L/R).
  --kp-scale-elbow FACTOR    per-family override (elbows L/R).
  --kp-scale-wrist FACTOR    per-family override (wrists L/R yaw/pitch/roll).
  --kp-scale-head FACTOR     per-family override (head yaw/pitch).
  --kd-scale FACTOR          like --kp-scale but for damping (default 1.0).
                             Watch the kp/kd ratio: bumping kp without kd
                             reduces effective damping ratio and can ring.
  --kd-scale-{hip,knee,ankle,waist,shoulder,elbow,wrist,head}
                             per-family kd overrides; same group definitions
                             as the kp variants above. The ankle and waist
                             aliases multiply their split subgroups together
                             (same backward-compat semantics as --kp-scale-*).
  --kd-scale-ankle-pitch FACTOR  ankle_pitch_joint ONLY. MC publishes kd=3.0
                             vs trained 0.907 -> 3.31 matches MC. Under-damped
                             ankle_pitch is the usual cause of 'foot-feels-
                             springy' on fwd/back nudges at the ankle.
  --kd-scale-ankle-roll FACTOR  ankle_roll_joint ONLY. MC publishes kd=2.0
                             vs trained 0.907 -> 2.20 matches MC. Should be
                             LESS than the pitch knob for the same reason
                             the KP is lower (frontal plane is intrinsically
                             more rigid; less damping needed).
  --kd-scale-waist-yaw FACTOR  waist_yaw_joint ONLY. MC publishes kd=8.0 vs
                             trained 2.56 -> 3.13 matches MC. Trunk damping
                             is critical for nudge rejection: bumping kd is
                             usually safer than bumping kp.
  --kd-scale-waist-pr FACTOR   LEGACY alias: applies to BOTH waist_pitch and
                             waist_roll. MC publishes kd=5.0 vs trained
                             0.907 -> 5.51 matches MC. Prefer the per-axis
                             knobs below for new presets (see
                             --kp-scale-waist-pr rationale).
  --kd-scale-waist-pitch FACTOR  waist_pitch_joint ONLY. Composes with the
                             legacy --kd-scale-waist and --kd-scale-waist-pr
                             multiplicatively (default 1.0 = inherit). The
                             sagittal-axis push response is the ONE waist
                             metric where SONIC already exceeds MC (+45%
                             stronger); don't bump this above MC-match
                             without explicit fwd/back-nudge scan evidence.
  --kd-scale-waist-roll FACTOR  waist_roll_joint ONLY. Composes with the
                             legacy --kd-scale-waist and --kd-scale-waist-pr
                             multiplicatively (default 1.0 = inherit). The
                             lateral-axis push response under SONIC at the
                             combined waist_pr knob sits at -72% of MC's
                             resistance, AND the policy moves its commanded
                             target with the disturbance (gait tracker),
                             so the failure mode is not simply 'too soft'
                             or 'too damped'. Direction of trim must be
                             determined by a post-fix MC-vs-SONIC lateral
                             nudge scan; do NOT prescribe an a priori
                             value here without that data.
  --action-clip RAD          symmetric clip on the raw ONNX action
                             (action_il) BEFORE x2_action_scale (default
                             20.0, matches training-time
                             config.action_clip_value in
                             gear_sonic/config/manager_env/base_env.yaml).
                             Negative = disabled (parity tests only).
  --return-seconds SECONDS   soft-exit ramp duration (default 2.0). When
                             --max-duration trips, lerp target_pos from
                             the last policy command to default_angles
                             over SECONDS (deploy-mode PD active) before
                             shutdown -- prevents MC from snapping joints
                             back at handoff (red-fault on X2 Ultra).
                             Set 0 to disable (legacy immediate-shutdown).
  --target-lpf-hz HZ         REAL-DEPLOY ONLY: first-order EMA cutoff
                             applied to the published joint targets to
                             tame leg/waist jitter caused by noisy real
                             sensor obs. Bypassed in RAMP_OUT/SAFE_HOLD.
                             Default 0 (disabled). Sim parity profiles
                             MUST leave this at 0 -- the LPF is invisible
                             to --obs-dump (raw target preserved) but it
                             changes what the bus sees, which would
                             diverge from eval_x2_mujoco.py's reference.
                             Acts as the GLOBAL default for joints with
                             no per-group override (see --target-lpf-hz-*).
  --target-lpf-hz-leg HZ     Per-group override for legs (MJ joints 0..11
                             = hip+knee+ankle, both sides). <0 = inherit
                             global; 0 = disabled on this group; >0 = use
                             this cutoff. Default <0 (= inherit).
  --target-lpf-hz-waist HZ   Per-group override for the waist (MJ joints
                             12..14 = yaw/pitch/roll). Recommended 2-3 Hz
                             to kill the observed 2.0-2.5 Hz waist
                             resonance under SONIC active walking.
  --target-lpf-hz-arm HZ     Per-group override for the arms (MJ joints
                             15..28). <0 = inherit global. Raise above
                             global if teleop arm motion feels sluggish.
  --target-lpf-hz-head HZ    Per-group override for the head (MJ joints
                             29..30). <0 = inherit global.
  --log-dir PATH             write per-tick CSVs to PATH
  --intra-op-threads N       ONNX session threads (default 1)
  --imu-topic NAME           override IMU topic (default /aima/hal/imu/torso/state;
                             use /aima/hal/imu/torse/state on firmware that
                             ships with the SDK-example typo)
  --obs-dump PATH            DEBUG: dump the first CONTROL-tick obs
                             (tokenizer + proprioception + raw action) to
                             PATH as a binary blob and exit immediately.
                             Pair with --dry-run + --autostart-after for a
                             deterministic capture from a known robot pose.
                             See compare_deploy_vs_isaaclab_obs.py.
  --stand-default-pose PATH  YAML file capturing MC's STAND_DEFAULT pose
                             (configs/x2_stand_default_pose.yaml). When
                             provided, RAMP_OUT lerps to *this* pose and
                             HOLD_FOR_MC publishes it -- so the joints land
                             exactly where MC will resume from, eliminating
                             the takeover step. Empty = use default_angles
                             (legacy: ~12-34 deg snap on takeover).
  --hold-for-mc-timeout-s SECONDS
                             Stay alive after RAMP_OUT for up to SECONDS,
                             holding MC's STAND_DEFAULT pose, until MC's
                             first joint command arrives on the bus (then
                             exit cleanly). 0 = disabled (legacy: exit at
                             end of RAMP_OUT, MC bus is silent until bash
                             POSTs start_app). Recommended: 15.
  --hold-for-mc-sentinel PATH
                             Touch PATH on entering HOLD_FOR_MC. Used by
                             deploy_x2.sh to sequence start_app +
                             SetMcAction(STAND_DEFAULT) at the right
                             moment. Empty = no sentinel.
  --hold-for-mc-exit-sentinel PATH
                             When set, HOLD_FOR_MC stops auto-exiting on
                             the first MC publish (because MC boots in
                             PASSIVE_DEFAULT = zero torque -- exiting then
                             would let the robot go limp). Instead, the
                             deploy node waits for PATH to appear; bash
                             creates it once MC has been escalated all the
                             way back to STAND_DEFAULT. The hold-for-mc
                             timeout is still a hard upper bound.
  --mc-first-publish-sentinel PATH
                             Touch PATH the moment the takeover detector
                             sees its first non-self publisher on
                             /aima/hal/joint/{leg,waist}/command (= MC
                             has come back online, likely in PASSIVE).
                             bash uses this as a fast trigger to start
                             SetMcAction(JOINT_DEFAULT) without waiting
                             for MC's mode service to respond. Does NOT
                             trigger exit on its own (see exit-sentinel).
  --start-trigger-sentinel PATH
                             Boot into STANDBY (writer suppressed) and wait
                             for PATH to exist before advancing to INIT.
                             Lets bash launch deploy AHEAD of stop_app +
                             safety gate to overlap colcon build / ONNX
                             load / DDS discovery with the operator's
                             confirmation. Empty = boot straight to INIT.
  --ready-sentinel PATH      Touch PATH on the first STANDBY tick to tell
                             bash that subscribers / ONNX / takeover
                             detectors are armed and the safety gate can
                             be shown. Independent of start-trigger; safe
                             to use on its own.
  --soft-shutdown-trigger-sentinel PATH
                             Polled at 50 Hz in CONTROL state. When PATH
                             appears, deploy transitions to RAMP_OUT (same
                             code path as --max-duration) and follows the
                             full RAMP_OUT -> HOLD_FOR_MC -> exit-sentinel
                             handoff chain. Lets bash convert Ctrl-C into a
                             graceful shutdown so the robot stays under
                             torque through MC's PASSIVE_DEFAULT boot (no
                             zero-torque drop). Empty = legacy behaviour
                             (immediate exit on SIGINT, ~1-2 s drop while
                             MC boots back to STAND_DEFAULT).
  --input-type TYPE          {motion_file,zmq} (default motion_file). When
                             'zmq', the tokenizer reference window is
                             driven by a ZMQ 'pose' topic publisher
                             (mock-VLA helper or real GR00T VLA). With
                             'motion_file' (legacy) the deploy uses
                             --motion (or StandStill if --motion empty).
  --whole-body-teleop        HYBRID whole-body overlay: pad/kplanner session
                             runs as primary (unchanged); when the laptop's
                             token stream is FRESH and ENGAGED, the token
                             graph (--token-model) drives instead. Stream
                             loss or disengage falls back to the pad.
  --token-model PATH         Token-input ONNX for the overlay (metadata
                             graph_kind=any2any_token_deploy required).
  --token-zmq-host HOST      Token sender host (the operator laptop).
  --token-zmq-port PORT      Token sender port (default 5556).
  --dual-model PATH          NATIVE DUAL-HEAD graph (graph_kind=native_dual_head,
                             native_dual_head_onnx_export.py): one SONIC session
                             with the pose-ref AND smpl heads; the laptop's SMPL
                             intent stream is consumed in-binary (no token
                             service). Requires --whole-body-teleop and
                             --smpl-intent-port; --model/--token-model unused.
  --smpl-intent-port PORT    SUB endpoint for the laptop's pico_intent stream
                             (bound here, the sender connects; 5573).
  --smpl-intent-host HOST    Bind/connect host (default 0.0.0.0).
  --smpl-intent-connect      Connect instead of bind.
  --wb-stale-s S             Stream silence that releases the smpl head (0.5).
  --wb-warmup-s S            Engage warm-up before the smpl head drives (1.0).
  --wb-switch-ramp-s S       Action crossfade at a head switch (0.2).
  --operator-root-level M    Level the OPERATOR root (Pico SMPL pelvis) before the smpl obs:
                             off|zero|clamp:<deg>|offset:<deg> (default off; 2026-09-15).
  --no-wb-hold               On a link drop, release at once instead of
                             holding the smpl head on the latched window
                             while the robot is stable.
  --smpl-obs-dump PATH       Dual-head parity dump: per tick the window, base
                             quat, yaw_align, wrists and the 840-d smpl obs
                             (checked by gear_sonic/scripts/smpl_obs_parity.py).
  --zmq-pose-host HOST       Host of the ZMQ pose publisher (default localhost).
  --zmq-pose-port PORT       Port of the ZMQ pose publisher (default 5556).
  --zmq-pose-topic TOPIC     Topic prefix to subscribe to (default 'pose').
  --zmq-debug-port PORT      If > 0, bind a PUB socket on this port and
                             publish per-tick x2_debug telemetry frames
                             in the packed-binary wire format consumed by
                             gear_sonic/scripts/dump_x2_debug.py. 0 disables.
  --zmq-debug-topic TOPIC    Topic prefix for telemetry frames (default 'x2_debug').
  --wrist-bypass MODE        {off, ik} (default 'off'). When 'ik' AND
                             --input-type=zmq, OnControl overwrites
                             target_pos_mj for the 4 broken wrist DOFs
                             (left/right wrist_pitch + wrist_roll, MJ
                             indices {20,21,27,28}) with the latest IK
                             reference from the ZMQ pose feed BEFORE the
                             safety stack. SONIC still drives the other 27
                             DOFs (legs, waist, shoulders, elbows,
                             wrist_yaw, head). Use 'ik' for VR teleop /
                             VLA dataset recording where SONIC's wrist
                             attractor masks the operator's hand pose;
                             keep 'off' for sim-to-real fidelity tests so
                             the policy's own commands reach every joint.
  --pose-ref-stale-s SEC     Split-topology safety (--input-type=zmq).
                             Pose-ref age (s) at which the deploy trips
                             into SAFE_IDLE (legs locked, default angles,
                             4x kd, no policy inference). Default 0.5 s
                             (~25 dropped frames at 50 Hz). Set <=0 to
                             disable (equivalent to --disable-pose-ref-
                             watchdog). Pairs with --pose-ref-min-fresh-s
                             and the resume chord for recovery.
  --pose-ref-min-fresh-s SEC After a SAFE_IDLE trip, the wire must carry
                             fresh frames for this many seconds continuously
                             before ReadyToResume() flips true. Default 1.0.
                             Prevents a flapping wifi link from oscillating
                             in/out of SAFE_IDLE on each fresh frame.
  --disable-pose-ref-watchdog Hard-disable the pose-ref watchdog regardless
                             of other flags. Restores legacy 'hold last good
                             frame on starvation' behaviour. Use only for
                             parity tests / benchmarks; NOT recommended for
                             split-topology production (the freeze-while-
                             leaning failure mode is exactly what this
                             watchdog catches).
  --zmq-resume-host HOST     Operator chord PUB host (the laptop running
                             quest3_manager_x2.py). Default 'localhost'.
                             In split topology pass the laptop IP.
  --zmq-resume-port PORT     Resume PUB port (default 5566).
  --zmq-resume-topic TOPIC   Resume topic (default 'pose_resume'). The
                             Quest 3 manager publishes a single multipart
                             message [topic, ts_monotonic_ns_le_i64]
                             when the operator holds A+B for 1 s on the
                             left controller.
  --mc-mode-poll-s SEC       Poll the MC GetMcAction service every SEC
                             seconds in a background timer (default 1.0).
                             Publishes the current McAction.value on
                             x2_debug as mc_action_mode for forensic
                             cross-correlation with policy/state. Set <=0
                             to disable (e.g. for sim runs where MC isn't
                             present). Pure observability -- the deploy
                             never acts on the result; the motor monitor
                             daemon owns the alerts + JSONL persistence.
  --mc-mode-service NAME     Override the MC mode service name
                             (default '/aimdk_5Fmsgs/srv/GetMcAction').
  --help, -h                 show this help
